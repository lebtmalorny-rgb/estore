OceanStor eStor T35 — ESXi 8, English по умолчанию

Пути к образам и материалам сборки приведены для исходного комплекта эмулятора.

ГОТОВЫЙ ФАЙЛ
../OceanStor_eStor_T35_ESXi8_EN.ova
Контрольная сумма: ../OceanStor_eStor_T35_ESXi8_EN.ova.sha256

ЧТО ВНУТРИ
Одноконтроллерный эмулятор OceanStor Dorado V6.
Встроенный manifest: 6.1.2 / V600R005C11, build 7600506206,
ReleaseTime 20210819161317 (19 августа 2021).
Исходный пакет: HUAWEICLOUD_OceanStor_eStor_V1R1C00T35_single_controller.qcow.
Это адаптация образа эмулятора, а не официальная поставка Huawei для ESXi.

КОНФИГУРАЦИЯ
- 8 vCPU, 16 GiB RAM — по шаблону FusionCompute из того же архива T35.
- BIOS, VMware virtual hardware 10; эта версия аппаратуры поддерживается ESXi 8.
- LSI Logic parallel SCSI.
- SCSI 0:0: система, 20 GiB; в гостевой ОС ожидается /dev/sda.
- SCSI 0:1: отдельный пустой диск данных 240 GiB; ожидается /dev/sdb.
- Пять E1000, ethernet0–ethernet4, как пять сетевых адаптеров исходного OVF T35.
- Все адаптеры используют логическую сеть eStor-Lab.
- Размеры ресурсов взяты из исходного шаблона, не из измерений под нагрузкой.

ИМПОРТ В ESXi 8
1. Host Client: Virtual Machines -> Create / Register VM ->
   Deploy a virtual machine from an OVF or OVA file.
   В vCenter: Deploy OVF Template.
2. Выберите OceanStor_eStor_T35_ESXi8_EN.ova.
3. Выберите datastore и Thin provisioning.
4. Сопоставьте eStor-Lab с port group лабораторного стенда.
5. Снимите автоматическое включение после импорта; проверьте порядок дисков,
   BIOS, LSI Logic, 8 vCPU (1 сокет × 8 ядер), 16 GiB RAM и пять E1000.
6. Включите ВМ и откройте консоль. Пройдите встроенную первичную настройку:
   IP, маска, шлюз, параметры узла, серийный номер и тип SAS/NVME.
   Используйте адреса своего стенда. Назначение сетевых адаптеров уточняйте
   по MAC и фактическим eth-интерфейсам в гостевой системе.
7. После запуска компонентов откройте https://<IP-эмулятора>:8088/.
   Порт 8088 указан во встроенном nginx_simu.conf.
   Для явного выбора английского: https://<IP-эмулятора>:8088/?language=en

Если мастер не принимает OVA, используйте находящиеся в этой папке OVF
и оба VMDK. MF храните рядом, если инструмент импорта его использует.
VMDK имеют транспортный формат streamOptimized: импортируйте их через
мастер OVF/OVA, а не подключайте прямо из datastore как рабочие диски.

ДИСК ДАННЫХ
Диск 240 GiB создан пустым. Исходный скрипт run_step1.sh обнаруживает
дополнительный диск и при неудаче mount выполняет mkfs.ext3 -F для
/crash/emulator/disk. Для этой ВМ используйте только выделенный пустой
диск данных из пакета; не подключайте к ней диски с нужными данными.

ЯЗЫК
DeviceManager содержит английский и китайский интерфейсы:
assets/i18n/resource.en.json — 7385 ключей;
assets/i18n/resource.zh.json — 7409 ключей.
Также присутствуют английские и китайские ресурсы общих компонентов.
Русского набора ресурсов веб-интерфейса не найдено.

English установлен как значение по умолчанию для нового браузерного сеанса,
включая браузер с китайским языком. Явный выбор через интерфейс, URL,
localStorage или cookie сохраняется. Если браузер уже запомнил китайский,
выберите English либо откройте адрес с ?language=en.

Компоненты DeviceManager распаковываются при первом запуске. Поэтому
изменение выполняется в штатном startup_prepare.sh после их установки,
до запуска сервисов: меняется только резервный выбор языка в main.js
и vendor.js. Переключатель English / 中文 остаётся доступен.
Это настройка веб-интерфейса, не изменение системной локали EulerOS.
Первоначальная консольная настройка уже содержит английские приглашения.

АДАПТАЦИЯ ДИСКА
В копии изменены пути VirtIO -> SCSI в загрузчике, fstab, rc.local,
шаблонах разметки и двух симуляторных hook-скриптах.
В startup_prepare.sh добавлена настройка английского языка.
Итого: 15 файлов; 1227 отличающихся байтов диска, включая поле длины inode.
Все остальные байты гостевого диска совпадают с исходным QCOW2,
проверенным через промежуточный RAW. Ядро, initramfs и программные
пакеты Huawei не заменялись. Драйвер mptspi с зависимостями уже есть
в initramfs; драйверы LSI Logic и E1000 присутствуют в гостевой ОС.

ПРОВЕРЕНО ЛОКАЛЬНО
- Целостность исходного QCOW2 и обоих выходных VMDK: qemu-img check.
- Совпадение исходного QCOW2 с RAW перед адаптацией.
- Изменения копии ограничены указанными файлами и полями размера.
- Совпадение адаптированного RAW с системным VMDK пакета.
- Полное последовательное чтение обоих streamOptimized VMDK через vbox-img
  с повторным сравнением восстановленных VDI.
- Пустое содержимое диска данных.
- Синтаксис обоих изменённых JS, 8 сценариев выбора языка и повторное
  применение настройки без дополнительных изменений.
- XML OVF, ссылки/размеры файлов, параметры ВМ, SHA-256 manifest,
  порядок и содержимое USTAR/OVA, контрольная сумма готового архива.
- SHA-256 исходного RAR и извлечённого QCOW2 после работы не изменились.

ГРАНИЦЫ ПРОВЕРКИ
Импорт на ESXi 8, загрузка гостевой ОС и работа DeviceManager/iSCSI/REST
в этой сессии не выполнялись. Локальная проверка языка не заменяет
проверку страницы в работающем эмуляторе. Функциональность SAN, NAS,
HA и интеграция с OpenStack отдельно не проверялись.
OVF проверен на структуру; внешняя проверка XSD не выполнена, поскольку
schemas.dmtf.org был недоступен. ovftool локально отсутствует.
