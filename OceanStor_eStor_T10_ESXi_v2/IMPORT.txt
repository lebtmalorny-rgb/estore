OceanStor eStor T10, сборка v2: пакет для пробного импорта в VMware ESXi / vSphere

Пути к образам и материалам сборки приведены для исходного комплекта эмулятора.

ФАЙЛЫ
- Готовый OVA: ../OceanStor_eStor_T10_ESXi_v2.ova
- Альтернатива: OceanStor_eStor_T10_ESXi_v2.ovf, OceanStor_eStor_T10_ESXi_v2.mf и два VMDK из этой папки.
- Исходный VMDK и ранее созданный QCOW2 остаются отдельно, без изменений.

КОНФИГУРАЦИЯ
- 4 vCPU, 8192 MiB RAM.
- VMware virtual hardware 10, BIOS.
- LSI Logic parallel SCSI.
- SCSI 0:0: системный диск 20 GiB; гостевые данные совпадают с исходным образом.
- SCSI 0:1: отдельный пустой диск 40 GiB для данных эмулятора.
- Шесть E1000, ethernet0-ethernet5, логическая сеть eStor-Lab.
- Размер CPU/RAM и дополнительного диска выбран для первого запуска;
  это не результат измерения минимальных требований или проверки под нагрузкой.

ИМПОРТ
1. В vSphere запустите Deploy OVF Template и выберите OVA из Downloads.
   В ESXi Host Client: Create/Register VM -> Deploy a virtual machine from an OVF or OVA file.
2. Выберите datastore; для дисков используйте Thin provisioning.
3. Сопоставьте eStor-Lab с port group вашего лабораторного стенда.
   Все шесть адаптеров в этом пакете используют одну логическую сеть.
4. Перед включением проверьте: BIOS, два диска в указанном порядке,
   LSI Logic, 4 vCPU, 8 GiB RAM, шесть E1000.
5. Откройте консоль ВМ и выполните штатную начальную настройку eStor.

При использовании OVF вместо OVA передавайте OVF и оба VMDK из этой папки;
manifest MF должен лежать рядом, если выбранный инструмент его использует.
Не загружайте streamOptimized VMDK как готовый рабочий диск непосредственно
в datastore: пакет рассчитан на импорт через мастер OVF/OVA.

ВСТРОЕННОЕ ПОВЕДЕНИЕ ОБРАЗА
Внутри /crash/permitdir/total_run.sh выбирает дополнительный диск и при
неудаче mount выполняет mkfs.ext3 -F. Поэтому пакет уже содержит отдельный
пустой диск SCSI 0:1. При первом запуске он будет инициализирован гостевой системой.
Настройки образа ожидают интерфейсы eth0-eth5; загрузчик содержит net.ifnames=0.

ПОКОЛЕНИЕ
Это eStor с профилями Dorado V3, а не Dorado V6.
/crash/permitdir/OSM/conf/product.ini: ProductName=Dorado6000 V3
/crash/permitdir/OSM/conf/VERSION: Version=V300R003C00, BuildTime=20181218_100325
Форматирование пакета не меняет прошивку или поколение эмулятора.

ИЗМЕНЕНИЕ В СБОРКЕ V2
В первой сборке пустой диск данных не проходил последовательное чтение
Oracle vbox-img: VERR_EOF. В v2 оба транспортных VMDK пересозданы через
vbox-img Stream. Параметры ВМ, ёмкость дисков и гостевое содержимое сохранены.
Причина конкретного отказа vSphere без журнала его задачи не установлена.

ПРОВЕРКИ ПАКЕТА
- Оба VMDK прошли полное последовательное чтение через vbox-img --stdin.
- OVF прошел xmllint --schema по официальной схеме DMTF OVF 1.1.1
  с локальными копиями всех зависимостей XSD.
- qemu-img check: ошибок на обоих VMDK нет.
- qemu-img compare: исходный VMDK и системный VMDK пакета идентичны
  по гостевому содержимому (Images are identical).
- Оба VMDK имеют createType=streamOptimized; диск данных полностью нулевой.
- Проверены ссылки, размеры файлов, ресурсы ВМ, порядок файлов USTAR,
  SHA-256 всех файлов внутри архива и соответствие внешнему набору OVF.
- Исходный VMDK не изменен; SHA-256: fe2114ae6022e5364d071981a7c58a0159032b16209dddfc06b7da011fa627be
- OVA SHA-256: a3d0bc9bfad0681a96b82ecc654fd92907dfff8c39355406d417c11012ab85fa

ГРАНИЦЫ ПРОВЕРКИ
Фактический импорт, загрузка и работа сервисов на ESXi пока не проверялись.
Потоковый тест использовал самостоятельную утилиту vbox-img; полноценный
импорт всей ВМ и загрузка гостевой системы локально не выполнялись.
